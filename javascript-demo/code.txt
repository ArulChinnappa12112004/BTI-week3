It sounds like you're learning JavaScript (var, let, null, Map, type casting with strings). Here's a single program that demonstrates all these concepts with explanations.

1. var vs let and Block Scope
console.log("=== var vs let ===");

if (true) {
    var a = 10;
    let b = 20;

    console.log("Inside block:");
    console.log("a =", a);
    console.log("b =", b);
}

console.log("Outside block:");
console.log("a =", a); // Works

// console.log("b =", b); // Error: b is not defined

Explanation
var is function-scoped, not block-scoped.
let is block-scoped.
Variables declared with let are accessible only inside {} where they are declared.
2. Array Type and Internals
console.log("\n=== Array Type ===");

console.log(arr);
console.log(typeof arr);
console.log(Array.isArray(arr));

Output
[10, 20, 30]
object
true

Explanation

Even though it's an array:

typeof arr


returns:

object


because arrays are internally specialized objects.

3. Null

console.log(typeof value);

Explanation

null represents an intentional absence of value.

Interestingly:

typeof null


returns "object" due to a historical JavaScript bug that was never changed for compatibility reasons.

In JavaScript, both == and === are used for comparison, but they behave differently.

== (Loose Equality)
Compares values after type conversion (coercion).
JavaScript tries to convert operands to the same type before comparing.
console.log(5 == "5");      // true
console.log(true == 1);     // true
console.log(false == 0);    // true
console.log(null == undefined); // true

Internal Conversion
5 == "5"


JavaScript converts "5" to number:

5 == 5


Result:

true

=== (Strict Equality)
Compares value and datatype.
No type conversion is performed.
console.log(5 === "5");     // false
console.log(true === 1);    // false
console.log(false === 0);   // false
console.log(5 === 5);       // true

Example
5 === "5"


Types are:

number === string


Since types differ:

false

Examples
console.log(10 == "10");   // true
console.log(10 === "10");  // false

console.log(true == 1);    // true
console.log(true === 1);   // false

console.log(null == undefined);   // true
console.log(null === undefined);  // false

Object Example
let a = [1, 2];
let b = [1, 2];
let c = a;

console.log(a == b);   // false
console.log(a === b);  // false

console.log(a == c);   // true
console.log(a === c);  // true


Arrays and objects are compared by reference, not by content.

Interview-Friendly Summary
==  → Compares only values after type coercion.
=== → Compares both value and datatype without coercion.

Best Practice

✅ Prefer === and !== in modern JavaScript because they avoid unexpected type conversions.

if (userId === 10) {
    console.log("Valid User");
}


This makes your code more predictable and less error-prone.

Number() and parseInt() are both used to convert values to numbers, but they work differently.

1. Number()

Number() tries to convert the entire value into a valid number.

console.log(Number("123"));      // 123
console.log(Number("123.45"));   // 123.45
console.log(Number("123abc"));   // NaN
console.log(Number("abc"));      // NaN

Rules
Number("100")      // 100
Number("100.5")    // 100.5
Number("")         // 0
Number(true)       // 1
Number(false)      // 0
Number(null)       // 0


If any invalid character is present:

Number("100px")    // NaN


because the whole string is not a valid number.

2. parseInt()

parseInt() reads the string from left to right and extracts the integer part until it encounters an invalid character.

console.log(parseInt("123"));      // 123
console.log(parseInt("123abc"));   // 123
console.log(parseInt("123.45"));   // 123
console.log(parseInt("abc123"));   // NaN

Rules
parseInt("100px")   // 100
parseInt("45.67")   // 45
parseInt("010")     // 10


It stops parsing when it finds a non-numeric character.

Comparison Examples
console.log(Number("100px"));    // NaN
console.log(parseInt("100px"));  // 100

console.log(Number("123.99"));   // 123.99
console.log(parseInt("123.99")); // 123

console.log(Number(""));         // 0
console.log(parseInt(""));       // NaN

Internal Behavior
Number()
Number("123abc")


Internally checks:

Is the entire string a valid number?


Result:

NaN

parseInt()
parseInt("123abc")


Internally:

1 → valid
2 → valid
3 → valid
a → stop


Result:

123

Interview Answer
Number()
- Converts the entire value to a number.
- Returns NaN if any part is invalid.
- Supports integers, decimals, booleans, null.

parseInt()
- Extracts and converts only the integer portion.
- Stops at the first invalid character.
- Useful when parsing values like "100px" or "45abc".

Best Practice

If you need strict numeric validation:

let age = Number(input);


If you need to extract an integer from a mixed string:

let width = parseInt("250px");


Output:

width = 250
